# OctoAcme Project Management Documentation

## Overview

This documentation suite describes how OctoAcme initiates, plans, delivers, releases, and improves cross-functional projects. It is designed to centralize project-management knowledge in a searchable, versioned set of process documents that supports consistent execution and faster onboarding.

OctoAcme's approach is grounded in:

- **Customer-first delivery:** prioritize customer value and usability.
- **Iterative delivery:** deliver small, testable increments and learn from results.
- **Clear ownership:** every project has named project and product leadership.
- **Data-informed decisions:** define success metrics, measure outcomes, and adapt.
- **Psychological safety:** encourage candid feedback, learning, and continuous improvement.

The lifecycle is **Initiation → Planning → Execution → Release → Retrospective**. Risks, communication, quality, and stakeholder alignment span every phase.

## How to Use These Docs in a Copilot Space

1. **Attach the relevant files or the `docs/` directory** to the Copilot Space so Copilot can use the process guidance as context.
2. **Begin with this README** to orient yourself, then open the document for the current project phase, role, or cross-cutting concern.
3. **Ask grounded questions** such as “What are the pre-release requirements?” or “How should this risk be escalated?” and reference the applicable process document when precision matters.
4. **Use the templates and checklists** in the documents as starting points for project one-pagers, backlog items, risk registers, status updates, release notes, and retrospectives.
5. **Keep the source documents current.** Propose process improvements through the repository's process-document issue template, and update the relevant document after stakeholder review.
6. **Treat project-specific artifacts as the source of truth** for current status, decisions, risks, and milestones; these process documents describe the standard way to manage that information.
